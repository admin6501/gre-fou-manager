# راهنمای فارسی

[صفحه اصلی](../README.md) · [English](README.en.md)

## نصب

روی ایران و خارج، هر دو:

```bash
curl -fL --proto '=https' --proto-redir '=https' https://raw.githubusercontent.com/admin6501/gre-fou-manager/main/install.sh -o install-gre-fou.sh
sudo bash install-gre-fou.sh
sudo gre-fou
```

نصب‌کننده ابزارهای لازم را نصب می‌کند، فایل مدیر را دانلود می‌کند و checksum آن را بررسی می‌کند. checksum دانلودشده امضای مستقل انتشار نیست. برای نسخه ثابت، شناسه یک commit موجود در همین ریپو را به `--ref` بدهید. برای استفاده از ابزارهای از قبل نصب‌شده، `--no-deps` را اضافه کنید.

اجرای دوباره نصب‌کننده، کد مدیر و فایل‌های سرویس را به‌روز می‌کند و کانفیگ تونل‌ها را جایگزین نمی‌کند. تونل فعال تا زمان ری‌استارت با همان اینترفیس قبلی کار می‌کند. برای اعمال تغییرات کد شبکه، از گزینه ری‌استارت هر تونل استفاده کنید.

## معنای آدرس‌ها

هنگام ساخت روی ایران:

| فیلد | مقدار |
|---|---|
| IP همین سرور | IPv4 ایران که روی اینترفیس سرور وجود دارد |
| IP سرور مقابل | IPv4 خارج |
| پورت UDP همین سمت | پورت دریافت FOU ایران |
| پورت UDP سمت مقابل | پورت دریافت FOU خارج |
| IP داخلی همین سمت | آدرس خصوصی سمت ایران در شبکه /30 |
| IP داخلی سمت مقابل | آدرس خصوصی سمت خارج در همان شبکه /30 |
| کلید GRE | شناسه مشترک دو سمت؛ رمز نیست |
| MTU | پیش‌فرض 1380؛ باید با ظرفیت مسیر سازگار باشد |

ایران و خارج نقش پروتکلی متفاوتی ندارند. هر دو می‌توانند آغازکننده ساخت باشند؛ «همین سرور» همیشه سروری است که منو روی آن اجرا می‌شود.

## ساخت اولین تونل

1. روی ایران، گزینه «۱. ساخت تونل» را بزنید.
2. یک نام مثل `ir1fr1` انتخاب کنید. نام باید با حرف کوچک انگلیسی شروع شود و حداکثر ۱۱ حرف کوچک یا عدد داشته باشد.
3. IPها را وارد کنید. برای قبول مقدار پیش‌فرض هر سؤال، Enter بزنید.
4. لینک تنظیمات چاپ می‌شود. روی خارج، گزینه «۲. نصب از لینک سمت مقابل» را بزنید و لینک را وارد کنید.
5. لینک، IP و پورت‌های دو طرف را برعکس می‌کند. کلید و MTU حفظ می‌شوند. فورواردهای ایران به خارج کپی نمی‌شوند.
6. روی ایران، گزینه «۴. مدیریت یک تونل» را بزنید، نام تونل را وارد کنید و «۹. تست و عیب‌یابی» را اجرا کنید.

لینک رمزنگاری یا امضا ندارد. فقط لینک مورداعتماد را وارد کنید. اگر یک پورت یا شبکه داخلی روی خارج قبلاً استفاده شده، مقدار مناسب را روی ایران ویرایش کنید و لینک تازه بگیرید. نام تونل در دو سرور می‌تواند متفاوت باشد.

## فوروارد پورت

روی سروری که کاربران به آن وصل می‌شوند، مدیریت تونل و سپس «۶. افزودن فوروارد» را انتخاب کنید. نمونه ورودی:

```text
both
2082,2053,3000-3010
```

در سؤال پورت مقصد، Enter یعنی شماره پورت مقصد همان شماره ورودی باشد. برای تبدیل پورت، فقط یک پورت ورودی مشخص کنید؛ مثلاً ورودی `443` و مقصد `8443`.

دستورهای معادل برای تونل `ir1fr1`:

```bash
sudo gre-fou forward-add ir1fr1 both 2082,2053
sudo gre-fou forward-add ir1fr1 tcp 443 --target 8443
sudo gre-fou status ir1fr1
sudo gre-fou forward-delete ir1fr1 1
```

شماره دستور حذف را از فهرست `status` بخوانید. TCP و UDP دو ردیف جدا هستند.

در خارج، سرویس مقصد باید روی `0.0.0.0` یا IP داخلی خارج گوش بدهد. سرویسی که فقط روی `127.0.0.1` یا IP عمومی گوش می‌دهد از این فوروارد در دسترس نیست. خارج IP داخلی ایران را به‌عنوان مبدا اتصال می‌بیند. تست اتصال به پورت عمومی ایران را از دستگاه سوم انجام دهید؛ مسیر OUTPUT محلی پیاده‌سازی نشده است.

## چند خارج به یک ایران

برای هر خارج یک تونل مستقل بسازید. نمونه زیر فقط آدرس‌های داخلی و پورت‌های مورد استفاده را نشان می‌دهد:

| اتصال | پورت UDP ایران | پورت UDP خارج | IP داخلی ایران | IP داخلی خارج | پورت ورودی کاربران |
|---|---:|---:|---|---|---:|
| `ir1fr1` | 5555 | 6665 | 10.240.0.1 | 10.240.0.2 | TCP/UDP 2082 |
| `ir1tr1` | 5556 | 6666 | 10.240.0.5 | 10.240.0.6 | TCP/UDP 2083 |

یک ترکیب IP عمومی، شماره پورت و پروتکل ورودی فقط می‌تواند یک مقصد داشته باشد. همین IP و پورت ورودی هم‌زمان به هر دو خارج فوروارد نمی‌شود.

## چند ایران به یک خارج یا چند ایران به چند خارج

برای هر زوج موردنیاز یک تونل بسازید و لینک آن را روی سرور مقابل وارد کنید. روی هر سرور، پورت FOU و شبکه /30 هر تونل باید مستقل باشد. ساخت تونل برای تمام زوج‌ها اختیاری است؛ این مدیر بالانس یا انتخاب خودکار خارج انجام نمی‌دهد.

## فایروال

- روی هر دو سمت، UDP پورت محلی FOU را از IP سرور مقابل اجازه دهید.
- روی ایران، پورت ورودی کاربران را باز کنید و FORWARD رفت و برگشت آن را اجازه دهید.
- روی خارج، INPUT سرویس مقصد از اینترفیس تونل و IP داخلی ایران باید مجاز باشد.
- فایروال پنل دیتاسنتر هم باید UDP دو طرف را اجازه دهد.

نام اینترفیس `gf` به‌اضافه نام تونل است؛ برای `ir1fr1` می‌شود `gfir1fr1`. نام جدول nftables آن `gfm_ir1fr1` است.

مدیر جدول اختصاصی هر تونل را می‌سازد. قوانین آن، DROP در جدول‌ها و فایروال‌های دیگر را خنثی نمی‌کنند. فایروال کل سرور پاک یا غیرفعال نمی‌شود. فوروارد کردن، `ip_forward` را فعال می‌کند؛ حذف تونل این تنظیم سراسری را خاموش نمی‌کند تا سایر سرویس‌ها قطع نشوند.

## مانیتور و وضعیت

```bash
sudo gre-fou status
sudo gre-fou diagnose ir1fr1
sudo gre-fou logs ir1fr1
sudo gre-fou monitor ir1fr1 on
sudo gre-fou monitor ir1fr1 off
```

مانیتور پیش‌فرض خاموش است. در صورت فعال‌سازی، تقریباً هر دقیقه IP داخلی مقابل را ping می‌کند. بعد از سه بررسی ناموفق، تونل محلی را ری‌استارت می‌کند. اگر ICMP مسدود باشد، مانیتور ممکن است تونل سالم را هم ری‌استارت کند. برای وضعیت timer:

```bash
sudo systemctl status gre-fou-health@ir1fr1.timer --no-pager
```

active بودن سرویس یعنی ایجاد محلی تونل موفق شده؛ به معنی دسترسی به خارج نیست. RX/TX از زمان ساخت اینترفیس محاسبه می‌شوند و با ری‌استارت یا ریبوت صفر می‌شوند.

## توقف، ویرایش و حذف

```bash
sudo gre-fou stop ir1fr1
sudo gre-fou start ir1fr1
sudo gre-fou restart ir1fr1
sudo gre-fou link ir1fr1
```

`start` بوت خودکار را فعال می‌کند و `stop` آن را غیرفعال می‌کند. ویرایش از منو انجام می‌شود. تغییر IP، پورت، کلید یا شبکه داخلی باید در سمت مقابل هم هماهنگ شود. اگر شروع سرویس پس از ویرایش خطا بدهد، مدیر برای بازگردانی کانفیگ قبلی تلاش می‌کند و خطای بازگردانی را هم گزارش می‌دهد.

حذف از منو با واردکردن دوباره نام تونل تأیید می‌شود. دستور غیرتعاملی زیر بدون تأیید اجرا می‌شود و همان تونل را حذف می‌کند:

```bash
sudo gre-fou remove ir1fr1
```

## بکاپ

```bash
sudo gre-fou backup /root/gre-fou-backup.json
sudo gre-fou restore /root/gre-fou-backup.json
```

بکاپ شامل تنظیمات است و ترافیک تجمعی یا اتصال‌های فعال را نگه نمی‌دارد. بکاپ روی فایل موجود نوشته نمی‌شود. بازیابی هم تونل با نام موجود را جایگزین نمی‌کند؛ تنظیمات بازیابی‌شده را باید با `start` فعال کنید. بکاپ مخصوص IPهای همان سرورهاست؛ انتقال به سرور دیگر نیازمند تغییر IPهاست.

## محدودیت و رمزنگاری

نسخه فعلی IPv4 مستقیم دارد؛ NAT، IPv6، WireGuard، رمزنگاری و بالانس اضافه نشده‌اند. GRE key شناسه است. با تنظیمات فعلی، سربار کپسوله‌سازی در IPv4 برابر ۳۶ بایت برای هر بسته IP است؛ این عدد سربرگ Ethernet، ارسال مجدد یا بسته‌های کنترلی را شامل نمی‌شود.

ماژول‌های `fou` و `ip_gre` باید در کرنل موجود باشند و سرور اجازه NET_ADMIN داشته باشد. نصب ابزارها با apt-get و dnf پشتیبانی می‌شود، اما فهرست توزیع‌ها به معنی تست واقعی همه آن‌ها نیست.

## تست‌های انجام‌شده

در ۲ اکتبر ۲۰۲۶، ۲۸ تست منطق و نصب‌کننده موفق بودند. تست واقعی کرنل در GitHub Actions روی Ubuntu 24.04 هم ping تونل، فوروارد TCP و UDP، SNAT و حذف منابع را بررسی کرد و موفق بود. نصب از فایل منتشرشده با شناسه commit نیز در اجرای push تست می‌شود. این تست‌ها اندازه‌گیری سرعت یا پایداری مسیر واقعی ایران و خارج نیستند.
